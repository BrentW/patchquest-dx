# Licensing and provenance conventions

Public maintainer: **BrentW**. Use this identity for maintainer credits. Do not infer a legal name, email, copyright owner or exclusive authorship from a local machine, account or aesthetic approval. Commit author email is a separate setting: verify the maintainer's GitHub-provided noreply address before configuring it.

## Selected licenses

The platform uses **Apache-2.0** for code, tools, tests, synthetic examples, configuration templates and documentation. It supports broad reuse of a developer toolkit and includes an express, limited contributor patent grant. The full [LICENSE](../LICENSE) governs; the [file-level scope](../LICENSE-SCOPE.md) identifies exceptions.

**Quest Pixel uses CC BY 3.0 Unported.** The visual reference already lists this license. Preserving applicable upstream terms under the same license avoids claiming an OFL relicensing grant and preserves the approved artwork. No OFL grant or redesign is part of this choice. License selection is distinct from proving all underlying rights; it does not cure a grant a contributor cannot make.

## Redistribution

For platform distributions, include Apache's license, retain applicable source notices, identify modified files prominently and carry forward applicable NOTICE content when supplied. No separate Apache NOTICE file is invented for this project. [Apache terms](../LICENSE).

For the designated font assets and their adaptations, retain creator/title/source credit, CC BY 3.0 terms and applicable notices; identify changes without implying endorsement. Do not add restrictions or effective technological measures that prevent exercise of the upstream licensed rights. CC BY permits commercial use and adaptation; it is not an exclusive-ownership assertion. Read the complete [CC legal terms](../assets/fonts/quest-pixel/LICENSE-CC-BY-3.0.txt) rather than treating this summary as a replacement.

Keep code and font licenses separate. A renderer does not become CC BY because it reads a font; glyphs do not become Apache because an Apache tool emits them. Distributable font atlases, tile/bitplane data, mappings and font-containing previews must retain the applicable font notices. In mixed packages, identify the font component separately from project code and other content. Ordinary text, factual metrics and other unprotectable matter acquire no exclusive copyright from a license label. ROM/patch publication still requires its own rights review; this platform license does not license a game's contents.

## Contributions and new assets

Before incorporating a new font, reference or borrowed asset, record its title, creator, source, license/version, applicable notices, acquisition basis and the nature of use. Distinguish visual reference, copied data, adapted artwork and independently developed code. Assess the contributor's authority and any upstream terms; attribution alone does not authorize reuse. If no adequate basis is established, keep the material private and report the specific unresolved issue.

Use the existing scope for contributions to the platform and Quest Pixel respectively. Contributors must identify borrowed portions, actual changes and any limitations on their ability to grant rights. AI assistance, redrawing, changing file formats and visual approval are not proof of independent creation or exclusive ownership. Do not invent a blanket copyright statement or silently substitute another license.

## Permanent maintenance by developers and agents

When a verified change affects an asset or its distribution, update the canonical provenance, [third-party notices](../THIRD_PARTY_NOTICES.md), file-level scope and relevant package generation together. Include complete applicable terms or an identified permitted reference, and make notices available with redistributed assets. Extend the public audit allowlist deliberately for newly approved notice files; a license file is not an exemption from privacy review.

Preserve approved glyph bytes and metrics; use sidecars to correct historical metadata. Generated appearance claims must be tied to a matching approval hash. Keep appearance approval, rights/licensing decisions and runtime testing separate. Avoid conflicting copies of policy: link to this guide and the scope instead of duplicating their full contents.

General licensing decisions and redistributable provenance belong publicly here. Detailed legal research, private comparisons, game evidence, machine paths and audit reports stay in the external private workspace. Neither public instructions nor a license permit publishing that workspace. No third-party contact, Git initialization, commit, remote creation, push or publication is authorized merely by preparing a candidate.
